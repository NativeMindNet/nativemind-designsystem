Order of precedence

The original GostSimBox icon is the mark. It is individually drawn per state, so a dense table stays scannable — that is exactly what a generic set loses. An emoji is the failover: it renders only when the image cannot be served (no asset pipeline, plain-text log, mail body, or a missing file). Never the other way round, and never both at once.

The marketing portal is plain HTML with no asset pipeline, so there the emoji is the icon. Country context uses the flag: 🇹🇭 Thailand, 🇷🇺 Russia, 🇬🇧 England — the language switcher is flags only.

Rules

The GostSimBox icon is the icon. Ship the file; reach for emoji only when the surface cannot serve one.
Wire the failover per image with onerror, so a missing file degrades to its glyph instead of a broken-image box.
Render at 16px, or an integer multiple (32/48/64) with image-rendering: pixelated. Never 24px, never 40px.
Status icons live in a fixed 26px centred column and always carry a title with the raw code (simst 255).
Signal strength has its own five-step set (rssi-0…4) — use it, not a bar gauge and not emoji.
Never an icon and its emoji side by side; the failover replaces the image, it does not accompany it.
Never recolour, tint or add a shadow to a glyph — the drawing itself is the semantic.
Never reuse one mark for two states in the same table, and never swap a state's mark between screens.
