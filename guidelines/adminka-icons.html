Adminka icon set

The original GostSimBox glyphs. These are the primary iconography for every status, quality, operator and hardware column — each mark is individually drawn and reads at a glance in a dense table, which a generic icon font does not. Emoji are a failover only, for when a file is missing or the surface cannot serve images.

Render size— integer scale, image-rendering: pixelated: no blur added
About resolution. Every file is 16×16, drawn pixel by pixel in the 2010s. There is no hidden higher-resolution version inside them, so anything larger is a reconstruction. Three honest routes, in order of preference:
  1. Integer upscale with nearest-neighbour — image-rendering: pixelated at exactly 2×, 3× or 4× (32/48/64 px). Every original pixel becomes a clean square; nothing is invented and nothing is blurred. This is what the switcher above does and what the design system uses by default. Non-integer sizes (24px, 40px) resample and must be avoided.
  2. Manual vector redraw — trace a glyph as SVG once, keeping the exact silhouette and palette. This is the only route to a genuinely sharp large icon. Worth doing for the ~20 glyphs that appear in headers and detail views; not worth it for 64 operator marks.
  3. Model upscaling — an image model can enlarge a 16px sprite, but it invents detail and drifts off the original palette, so the icons stop being recognisably the same set. Only acceptable with a human review of every glyph.
Practical rule: keep the 16px originals as the source of truth, render at 16 or 32 in tables, 48 in detail views, and redraw as SVG only where a glyph carries a headline.
