Adminka icon taxonomy

224 files, one flat sprite folder in 2015, now organised. Three things matter when reusing them: what each folder means (the grouping is the semantics), which marks are hand-drawn and therefore irreplaceable, and how a suffix variant relates to its base — a region badge stamped onto an operator logo, not a separate drawing.

1 · Grouping — folder = semantic axis

Each folder is one column of the panel, and one axis of meaning. A file name inside it is the raw protocol value, not a description — state/simst/255.ico is literally SIM status 255. That is why the set survived: the panel indexes it by value, so adding a state means adding a file, never touching code.

2 · Suffix variants — one base logo, one stamped badge

Region variants are not separate drawings. Each is the operator logo with a small letter or mark stamped in a corner — beeline_msk is Beeline plus an M for Moscow. Measured on an 8×8 luminance signature, Δ is how many of the 64 cells differ from the base file: a letter badge moves 2–9 cells, a recoloured or larger regional mark moves 18–25.

Rule when extending. Never redraw an operator. Take the base .ico, stamp the region letter in the same corner at the same size, save as <operator>_<region>.ico. Region codes are fixed: msk spb ru sz ural chel by u minsk gor mob.

3 · Provenance — Fugue-derived vs hand-drawn

The panel was built on Fugue (Yusuke Kamiyamane) and every reused glyph was renamed to its protocol value, so the original names are gone. Matching therefore has to be visual, not nominal. An 8×8 luminance signature per file is stored in assets/adminka/_sig-napravleine.json and _groups-napravleine.json — the same signature is what produced the Δ column above, and it is the hook for a full cross-match against the upstream 3 570-icon set when that set is available locally.

Fugue-derived Generic states and objects: call states, SMS, calendar days, lock/key, playback, magnifier, clock, balance. Renamed to codes, otherwise untouched. If one is missing or needs a sibling state, take it from Fugue 2× — same family, 32×32.

Hand-drawn, irreplaceable Nothing outside Fugue can substitute these — they encode a specific company or a specific piece of hardware:

  • napravleine/* — 33 operator and region marks (Beeline, MegaFon, MTS, Tele2, Rostelecom, Velcom, Life, Kyivstar, DNA, Elisa, Sonera, Saunalahti, Proper).
  • usb/hub_dlink, hub_hamma, hub_16, usb_pci, usb_port — actual hub models on the rack.
  • dongle173, dongle1550, pl2303, msm — modem and chipset models.
  • recog_types/10…120 — numeric confidence tiers.
  • qos/ipalevo, irob, ivip1/2, spec/carousel, notvip — domain slang with no generic equivalent.

Modified A base glyph with a stamped badge: the whole napravleine suffix family, plus state/state_sout_in / _sout_out (arrow overlay on the SOUT base) and high_datt / low_acdl shipping in both .ico and .png. Treat base and badge as separate layers when redrawing.

4 · Fugue 2× fallback, vendored

32×32 sources from chrisjbillington/fugue-2x-icons, rendered at 16px — same density as the originals on screen, sharp on HiDPI, and no pixelated for these. Use one only when no GostSimBox mark exists.
