Icon density

Icons have one logical size, not three. Every raster asset is prepared at 16×16, 32×32 and 48×48 in the same pass, and the runtime picks the bitmap that matches the device pixel ratio. The icon stays 16 logical px on screen everywhere; only its density changes.

The 16-logical-px row is the design-system default and the one every glyph must ship. A larger UI size is a different asset with its own three files — the 48 px file from the 16 px row is the @3× bitmap for a 16 px icon, not a 48 px icon.

Markup

<img
  src="power-16.png"
  srcset="power-16.png 1x,
          power-32.png 2x,
          power-48.png 3x"
  width="16" height="16"
  alt="">

Resolution switching via density descriptors. The browser loads the physical bitmap; the box stays 16 CSS px, so the PNG is pixel-for-pixel with no interpolation. Fixed width/height also prevents reflow.

/* failover keeps the same box */
.ic{width:16px;height:16px;display:block}
.ic--svg{width:16px;height:16px}   /* viewBox="0 0 16 16" */
.ic--emoji{width:16px;height:16px;
  font-size:16px;line-height:16px;
  text-align:center}

An onerror failover is metrically identical to the PNG it replaces: same 16-logical-px box, same baseline, same optical weight. Nothing shifts when a file is missing.

SVG and emoji failover — same typesizes

Vectors can render at any size, which is exactly why they need the rule. An SVG failover is drawn on a 16-unit grid (viewBox="0 0 16 16", whole-unit coordinates, 1-unit strokes) and placed in a 16 logical px box — at DPR 2 and 3 it lands on 32 and 48 device px, the same grid as the PNG triplet. Emoji get the same treatment: fixed 16×16 box, font-size:16px, no inherited line-height. Only the three sizes 16 / 32 / 48 are legal render targets, whatever the source format.

Two independent layers. Layout scaling — logical px → device px, handled by the runtime; the designer never draws a separate Retina or TV mock. Asset resolution switching — which of the three bitmaps is fetched, decided by DPR. Row height, type size, spacing and gaps are authored once in logical units.

Rules

  • Prepare 16 / 32 / 48 in the same pass. A glyph with only one size is not ready to ship.
  • Never scale a PNG in CSS — no 20px, 24px, 40px render of the 16px set. Non-integer resampling is the one thing this system exists to prevent.
  • The GostSimBox originals are true 16×16 art: their 32 and 48 are integer nearest-neighbour upscales (image-rendering: pixelated), not new drawings. Fugue ships real 32×32 and has 48×48 PSD sources — use the real density, no pixelated.
  • TVs follow DPR, not panel resolution: a 4K set often reports a 1920×1080 viewport at DPR 2. Target the ratio, never “4K”.
  • Large TV and detail surfaces get their own 48/96/144 triplet rather than an enlarged small icon.
